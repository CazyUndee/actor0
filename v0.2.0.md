# Actor0 v0.2.0 — Comprehensive Engineering Release Notes

This document is the full engineering record of every change that shipped in
v0.2.0, from the initial standalone project through the provider-menu and
global-model-picker redesign. It is written for auditors and for the next
person who has to reason about why a given behaviour exists: each entry
states what changed, why it was done that way, and what breaks if the
decision is reversed. The commit subjects in backticks are the verbatim
git log entries; the surrounding prose is the engineering rationale.

The version bump itself (0.1.1 → 0.2.0) was a `[feat]` commit that also
added the versioning rule to AGENTS.md: PATCH for any behaviour change,
MINOR for features/upgrades, MAJOR only on explicit user request, one
component per commit, reset lower components to 0, all three package.json
files (harness, providers, cli) plus the hardcoded fallback strings in
mcp.ts and parts.test.ts kept in sync.

---

## Headline — the biggest changes

1. **A real terminal renderer replaced Ink.** `cli: replace the Ink UI with our own terminal renderer` — a frame-based renderer with a pinned composer, scrollable transcript, and wheel/click handling. Every UI commit after it is a consequence.
2. **The harness boundary became real.** `packages/harness` imports nothing from the CLI; `check:boundaries` enforces it. The CLI exists to prove the boundary.
3. **Markdown is actually rendered.** The prompt promised fenced code blocks, tables, headings, lists, inline emphasis; the renderer now delivers them. (Previously one word-wrapper folded everything.)
4. **Context overflow is recovered, not fatal.** A turn that does not fit is compacted and retried, with the removed content reported.
5. **Eight tools, not six.** `rg` (ripgrep) and `glob` were added so the model stops shelling out; `read`/`edit`/`bash` hardened against real-world inputs.
6. **BYOK provider model.** Three transports (OpenAI-compatible, Anthropic Messages, ChatGPT/Codex), OAuth sign-in, provider registry, per-provider model lists.
7. **MCP server.** The CLI's own ToolHost is exposed to external MCP clients over stdio, plus a daemon that manages the tunnel.
8. **A tool-interface benchmark.** 216 commits of measurement discipline: four candidates, a verifier, an optimization loop, gap-aware verdicts, a 24-turn battery for new models.
9. **The TUI preview became a test, not a lie.** Three documented failure modes fixed; `show()` is now async and awaited.
10. **Release plumbing.** GitHub release with bundled CLI; npm publish workflow for the two libraries; versioning rule.

## 1. Harness — turn loop, streaming, recovery

### 1.1 Initial runtime
- `Initial commit: actor0 as a standalone project` — the first runtime.
- `Add the actor0 terminal client` — the CLI that proves the boundary.

### 1.2 Streaming correctness
- `Make a tool call's trailing newline independent of delta chunking` — a tool call's argument string must not depend on where the SSE stream happened to split. The newline is appended at parse time, not at delta time.
- `Make a delta boundary not tear a status line in half` — partial JSON at a chunk boundary was being parsed as a complete value. Buffering until a complete frame arrives prevents a status line from being split.
- `Pin the transport's chunk invariance, and fix a race in its own test server` — the transport must produce identical tool calls regardless of chunk boundaries; the test server race was masking failures.
- `Classify in-stream error frames instead of retrying every one of them` — not every error frame is retryable; classifying by type prevents a non-retryable error from burning all retries.
- `Honour Retry-After, and stop promising retries the message never mentions` — when the server sends Retry-After, use it; do not advertise a retry count the error message does not support.

### 1.3 Turn completion and abort
- `Keep a failed turn's completed rounds in the transcript` — a turn that errors mid-way still keeps the rounds that succeeded; rewinding them loses work and confuses the model.
- `Keep the results a turn is still reasoning about, on the save path` — results in flight at save time must be persisted, not dropped.
- `Persist a cancelled turn's exchange instead of rewinding the session` — Esc cancels the turn but the partial exchange is still valuable context; rewinding it makes the next turn re-ask.
- `Persist headless turns to a restored session; print the recovered fragment` — a `-p` headless turn that is later resumed must be in the session file.
- `Tell the model when a turn was stopped, not just the user` — the model needs to know its previous turn was interrupted so it does not assume its own output landed.
- `Say what a turn that stopped or was cut off actually did` — the user-facing summary of an aborted/cut-off turn must describe what completed, not just that it stopped.
- `Retire the needs_user banner on reply; commit pre-tool prose at the call` — the needs_user banner was replaced by committing the model's pre-tool prose at the tool-call boundary, so the transcript shows reasoning in order.
- `Keep a failed turn's completed rounds in the transcript` (see above).

### 1.4 Context overflow recovery
- `Recognise the size error the endpoint actually sends` — the endpoint sends `Message too large (50k char limit)`, not Anthropic-shaped prose. The whole recovery path was built against invented strings and was unreachable until measured against the real host.
- `Believe the window the endpoint states instead of guessing one` — use the endpoint's stated limit, not a guessed token count.
- `Recover a turn the model rejected for size, instead of ending it` — compact history and retry rather than terminating the turn.
- `Continue an answer the endpoint cut off, instead of saving the fragment` — a truncated answer is continued, not stored as-is.
- `Say what a context-overflow recovery took out of the conversation` — the recovery must report what was removed so the user is not surprised.
- `Bound the project context the model is sent on every request` — the project context (CLAUDE.md etc.) is bounded; a cut file says in its own text that it was cut.
- `Compact history by clearing stale tool results; fail loudly on bad flags` — compaction only ever clears tool payloads; never drops a message, never reorders, never cuts mid-conversation-unit (an orphaned tool result is rejected by the provider on every subsequent request).
- `Recover the intended tool name when rejecting a malformed block` — when a tool-call block is malformed, attempt to recover the intended name rather than dropping it silently.

### 1.5 Session persistence and repair
- `Repair broken tool pairing on session load, not only on save` — orphaned tool results are repaired at load time too, so a session saved by an older build can still be resumed.
- `Keep a literal dollar in the text an edit writes` — `String.prototype.replace` interprets `$$`, `$&`, `$'`, `` $` `` in a plain-string replacement. Edits now use `split(before).join(after)`, which is literal by construction.
- `Discard a dead attempt's mid-stream residue on retry` — on retry, partial output from the failed attempt must be discarded, not carried forward.
- `B66a5b0 Say what a turn that stopped or was cut off actually did` (see above).

### 1.6 Sub-agents and tool hosts
- `Reinstate sub-agent delegation (the task tool)` — the task tool was removed and then restored.
- `Harness: namespacedToolHost + compositeToolHost combinators` — tool hosts can be namespaced and composed, which is how MCP tools are merged into the CLI's host.
- `Refactor: extract @actor0/providers (transports + resolution + types)` — transports moved out of the harness into `packages/providers`, establishing the three-package boundary.

### 1.7 Tool rounds
- `turn: no tool-round cap by default — a long turn keeps working; maxToolRounds is now an opt-in config field` — previously a hard cap killed long turns; now uncapped by default with an opt-in limit.

## 2. Tools

### 2.1 Search and listing
- `CLI: replace the grep tool with ripgrep (rg)` — the grep tool was backed by a JS implementation; switching to ripgrep gives real regex, glob filtering, and speed. The TOOLS array order is the order the unknown-tool error lists.
- `Give the model a search, so it stops shelling out for one` — added `rg` so the model has a search primitive.
- `Give the model a listing, so it stops shelling out for one` — added `glob` so the model has a listing primitive. `glob` lists a directory and does not descend into it; a note names the ones it left alone (node_modules etc.). The note is scoped to the answer, not attached to every result.
- `tools: rg gets a default 30s timeout — a whole-tree search can no longer hang the bridge` — a whole-tree search previously had no ceiling.
- `CLI: allow read-only tools (read, glob, rg) to reach outside the working directory` — read-only tools are not confined to cwd; write tools are.

### 2.2 read
- `Stop `read` handing back one enormous line as if it were the file` — a file with one enormous line was returned as a single line; now line-bounded.
- `Refuse a file `read` cannot honestly return` — `read` refuses files it cannot return honestly (e.g. binary).
- `Stop a paged read from reporting the reader's own limit as the file length` — a paged read reported the page size as the file length.
- `Make the truncation notice say how much output actually went missing` — the truncation notice states how much was dropped.
- `read is safe at the limit by luck: its 50,000 byte cap lands at ~43,600 characters` — bytes vs characters; the enforced unit is characters.

### 2.3 edit
- `Keep a literal dollar in the text an edit writes` (see §1.5) — `split/join` instead of `replace`.

### 2.4 bash
- `Close the shell tool's stdin so a command cannot wait an hour for input` — stdin is closed so a command waiting for input cannot hang.
- `A shell command has no default timeout` — deliberately; a 120s default killed real installs. Ceiling is an hour.
- `Stop refusing directories that merely start with two dots` — `within()` path check was rejecting `../foo`-shaped names that are actually inside cwd.
- `f8faaaf [fix] child.stdin now swallows its own EPIPE` — a tool that ignores stdin no longer crashes the CLI via unhandled EPIPE. An error listener is attached to `child.stdin`.

### 2.5 web search / fetch
- `CLI: web search + page fetch via mst and webclaw` — web search and page fetch tools, shelling out to `mst` and `webclaw` binaries pinned by version and SHA256-verified on install.

### 2.6 skills
- `CLI: skills — progressive disclosure of reusable instructions` — skills are loaded on demand rather than always in context.
- `docs: design for the skills feature (progressive disclosure)` — the design document.

### 2.7 MCP client
- `CLI: MCP client (McpServer, connectMcp, mcpToolHost)` — the CLI can connect to external MCP servers and merge their tools into its host.
- `Harness: namespacedToolHost + compositeToolHost combinators` (see §1.6).

### 2.8 repo index
- `CLI: repo index + shallow file tree in the prompt` — a shallow file tree and repo index are injected into the system prompt so the model does not shell out to list files.

## Appendix A — the dist trap (must read before editing harness)

The CLI resolves `@actor0/harness` and `@actor0/providers` to their built
`dist/`, not to `src/`. After changing anything under `packages/harness/src`
or `packages/providers/src`, run `npm --workspace @actor0/harness run build`
(and providers) before running CLI tests, or the CLI throws "does not
provide an export named …" for a symbol that is plainly there. `npm test`
at the root builds first, so the full suite is safe; a bare
`node --import tsx --test src/turn.test.ts` in `apps/cli` is not. Reverting
harness source and re-running CLI tests proves nothing — the CLI keeps
loading the built copy.

## Appendix B — commit discipline

Every change is committed the moment it is in a coherent state. Stage
